# Feedback dataset

The owner's judgments of generated music, kept as data from the start so they can later evaluate
generators, train a reward model, or fine-tune one (see [`ROADMAP.md`](../ROADMAP.md)). Read and
write it with `music_ai.feedback` (`load`, `save`, `check`); `tests/test_feedback.py` checks that the
committed tables are consistent.

| File                | One record per                         | Key fields                                                         |
| ------------------- | -------------------------------------- | ------------------------------------------------------------------ |
| `generations.jsonl` | generated piece                        | `id`, `experiment`, `task`, `arm`, `output`, `brief`, `context`, `prompt`, `model`, `generator`, `commit`, `as_generated`, `edits` |
| `ratings.jsonl`     | rater × piece                          | `generation`, `scores` (1–5: `brief`, `musicality`, `playability`; from 003 also `difficulty`, descriptive), `notes`, `blind`, `heard` |
| `preferences.jsonl` | rater × set of pieces for one brief    | `candidates`, `chosen`, `blind`                                    |

Conventions:

- Generation ids are `<experiment number>/<arm>/<task>[-<sample>]`, e.g. `002/B/T1-1`.
- `output` is the file as it is now. If it was corrected after generation, the original is kept at
  `as_generated` and `edits` says what changed. A rating's `heard` names the version actually
  judged when that wasn't `output`. A corrected file plus its original is itself a useful
  (better, worse) pair.
- Paths are repo-relative. Context files under `data/` (e.g. corpus excerpts) are gitignored and
  rebuilt by scripts, so `check` doesn't require them.
- Tables are append-only in spirit: add records, and fix mistakes by re-running the script that
  produced them rather than by hand.

Free-text feedback that covers a whole set of pieces rather than one goes in `comments/`, one
Markdown file per experiment (e.g. `comments/003-general.md`).

Contents so far: experiments 001 and 002 (32 pieces), imported by `scripts/backfill_feedback.py`
from the blind-judging pages, and 003 (10 hymn arrangements), recorded by `scripts/record_003.py`.
All were generated by Claude Opus 5.5 as Claude Code teammate agents.

Note on use for training: these outputs come from a hosted model whose terms restrict using
outputs to train other models. The ratings and notes are the owner's own; check the terms before
fine-tuning on the generated pieces themselves.
